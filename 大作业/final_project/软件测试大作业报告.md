## 2. 测试目标和方法

**测试目标：**

- 目标1：验证ECShop前台页面基本浏览功能，包括窗口控制、页面导航、元素交互
- 目标2：验证ECShop后台管理系统的Frame切换、验证码处理及元素定位
- 目标3：通过Selenium自动化脚本覆盖大作业要求的全部11个核心技术点

**测试方法：**

- 方法1：黑盒测试——编写Selenium自动化脚本模拟用户操作流程，覆盖前台浏览和后台管理
- 方法2：断言验证——通过获取页面元素属性（`is_enabled()`、`is_selected()`、`get_attribute()`）和文本（`element.text`）来判断操作是否成功
- 方法3：截图验证——对关键操作步骤保存17张截图作为测试证据，包括全屏截图和元素截图

**测试来源：**

本测试整合了平时模块二的9个实验：实验05（浏览器基本操作）、实验06（页面元素基本操作）、实验07（模拟键盘操作）、实验08（模拟鼠标和键盘操作）、实验09（消息框操作）、实验10（切换浏览器窗口）、实验11（切换Frame）、实验13（截屏操作）、实验14（验证码测试）。

### 8.3 遇到的困难及学到的经验

**困难1：元素定位失败——ECShop首页不存在"所有分类"链接。**

- **原因分析：** 编写脚本时凭猜测使用了"所有分类"作为悬停目标，但ECShop V2.7.1首页实际不存在该元素。
- **解决方案：** 改用实验03/08确认存在的"登录"链接替代，参考平时实验的辅助脚本模式——先写查找脚本确认元素实际名称，再写选择器定位。定位采用 `By.LINK_TEXT → By.PARTIAL_LINK_TEXT → XPATH(href)` 三级回退。
- **经验总结：** 编写自动化脚本前应先探查页面实际DOM结构（如实验03的 `查找页面元素.py`），使用 `find_elements(By.TAG_NAME, "a")` 遍历确认所有链接的真实文本，而非凭猜测写选择器。

**困难2：alert打开期间无法截图——`UnexpectedAlertPresentException`。**

- **原因分析：** `driver.save_screenshot()` 需要通过WebDriver协议向浏览器发送命令，但浏览器原生alert/confirm是模态对话框，弹出期间锁死整个WebDriver线程，所有WebDriver命令都被阻塞。
- **解决方案：** 将截图时机从"alert打开期间"移至"accept()/dismiss()关闭之后"。关闭后的截图同样能证明alert已成功处理。
- **经验总结：** Selenium处理alert的正确顺序是 `switch_to.alert → text获取 → accept/dismiss → 继续操作`。alert打开期间只能执行Alert对象的方法（`text`、`accept()`、`dismiss()`、`send_keys()`），不能执行任何driver级命令。

**困难3：ECShop后台使用frameset布局，元素藏在不同Frame中。**

- **原因分析：** 后台页面由多个frame组成（header-frame、menu-frame、main-frame），直接在主文档中定位元素会失败。
- **解决方案：** 参照实验11/12/13的标准做法：先用 `switch_to.frame("menu-frame")` 操作菜单，再用 `switch_to.default_content()` 回到主文档后 `switch_to.frame("main-frame")` 操作内容区。
- **经验总结：** 遇到iframe/frame嵌套页面时，必须先了解页面层级结构，逐层切换。`default_content()` 是回到主文档的唯一途径。

**困难4：商品详情页结构因模板差异，元素选择器不稳定。**

- **原因分析：** 不同商品模板的HTML结构可能不同（如h1标签不一定存在），固定选择器会失败。
- **解决方案：** 使用多级回退策略——先尝试XPATH定位h1，失败则尝试id/class选择器，再失败则从 `driver.title` 或 `page_source` 正则提取数据。参考了实验06从 `driver.page_source` 正则提取库存信息的方式。
- **经验总结：** Selenium定位元素时应优先使用语义化属性（id、name），XPATH尽量用 `contains()` 做模糊匹配。关键数据提取如果用DOM方式失败，fallback到 `page_source` + 正则提取。

### 8.4 改进方向

1. **引入显式等待（WebDriverWait）替代固定 `sleep()`：** 当前脚本使用 `sleep()` 固定等待，在网络较慢时可能不够，网络快时又浪费时间。应使用 `WebDriverWait` + `expected_conditions` 实现条件等待（如等待元素可点击、alert出现），提高执行效率和稳定性。

2. **封装为unittest/pytest测试框架：** 当前为单脚本顺序执行，应将7个阶段封装为独立的测试方法（`test_window_ops()`、`test_keyboard()`、`test_mouse_actions()` 等），使用 `setUp()` / `tearDown()` 管理浏览器生命周期，支持独立运行和结果统计。

3. **增加数据驱动测试：** 可引入CSV/JSON配置文件驱动测试数据（如不同搜索关键字、不同登录账号），覆盖更多边界场景，提升测试覆盖面。

4. **增加前台验证码OCR识别：** 当前后台使用万能验证码"0"绕过，前台评论场景可集成 ddddocr（实验14已验证可行性）实现验证码自动识别，覆盖更完整的业务场景。
